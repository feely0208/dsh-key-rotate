# 密钥轮换

查密钥与证书**多久没换了**、有没有**轮换制度**、有没有**跨环境复用**。

## 一、何时用

- 安全自查、等保测评前的准备
- 客户尽调、供应商安全评估
- 交接、审计
- 定期（建议每季度）

## 二、它查什么

| 级别 | 项 | 依据 |
|---|---|---|
| 🔴 高 | **密钥/证书文件超过一年未更新** | 等保「鉴别信息应定期更换」· NIST SP 800-57 密码周期 |
| 🟡 中 | **找不到轮换策略** | 等保 安全管理体系 · 安全管理制度 |
| 🟡 中 | **同一密钥在多个环境配置中被引用** | 等保 访问控制 · 最小权限 / 按环境隔离 |

## 三、为什么「多久没换」是可判定的

密钥轮换看似是管理问题，但**文件年龄是硬数据**：

```
密钥文件的 mtime  →  距今多少天  →  对比阈值（默认 365 天）
```

一个 400 天没动过的 `id_rsa`，无论制度写得多好，**事实上就是没换**。

## 五、边界

- **年龄 ≠ 未轮换**：文件可能被重新生成但保留原名与时间戳；也可能密钥存在 KMS 里、
  本地只是副本。本工具报的是「这个文件很久没变」，**需你确认它是否还在用**。
- **不解析证书内容**：不校验证书有效期、签发者、密钥长度 —— 只做文件层面的检查。
- **不查密钥是否已泄露**：那需要比对泄露库，不在范围内。
- **跨环境复用只查 .env 类文件**：密钥写在 KMS / CI secrets 里的情况看不到。
- 与 `dsh-secret-scan` 的分工：那个查「密钥有没有被提交」，这个查「密钥有多久没换」。
